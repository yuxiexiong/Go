# 精读报告：Engels et al. 2025 与 Marks et al. 2025（2026-11-26）

## 坏消息先说

1. **两篇都没有超人系统，也都没有棋类引擎。** Engels 的被监督方和监督方全是 LLM（Arena Elo 1103–1377）。Marks 的被审计方是 Claude 3.5 Haiku，审计方是人类团队。两篇都没有呼吁用"真正超人的系统"做测试床，所以我们不能写"回应了他们提出的 future work"。Engels 提的方向是 RLHF、SFT、AI control 环境，以及用微调代替提示扮演对手。Marks 提的方向是"目标从训练中自然涌现、更真实的测试床"。我们的"超人 + 植入真值"组合在这两篇里**没有被占**，但也**没有被它们点名需要**。痛点要另外论证。
2. **Marks 的核心经验会直接威胁我们的设计（推导档）。** 他们三个成功团队靠的都是**训练数据访问**：找到占语料 0.01% 的合成文档。而且一个简单的语义搜索基线就能复现最快团队（SAE 组，1.5 小时）的路径（§5.1、§5.4）。如果我们用训练数据植入 komi 触发的后门，任何拿到训练数据的审计方，只要搜异常 komi 的样本就会直接解题，检出率与 Elo 差无关。
3. **komi 触发本身可能让"随 Elo 差缩放"这条曲线测不出来（推导档）。** komi 是一个取值范围小、可以穷举的标量输入。黑盒审计方扫一遍 komi，比较落子分布，不需要任何棋力就能发现异常。检出率会在所有 Elo 差下饱和，与 Elo 差无关。触发器应放进盘面模式这类高维空间，并且合同里要预先排除"扫输入通道"这条捷径，或者把它单列为一种审计类型。
4. **Engels 的 Fig.13 是我们"超人新颖性掩护"假说的反面先例（类比档）。** 他们发现，在后门可用的条件下，更强的 Houdini 写出的后门并不更难被识破：强模型只是能造出更多可用后门，并不更隐蔽。我们的假说预测的是隐蔽性随被审方强度上升，方向相反。他们的场景是 LLM 写代码，能否迁移到引擎没有验证，但它是审稿人会拿来对照的先例。
5. **Engels 的拟合只覆盖约 274 点 Arena Elo，400 点处的数字是外推。** NSO 在 Δgeneral=400 时的成功率（Mafia 13.5%、Debate 51.7%、Backdoor Code 10.0%、Wargames 9.4%）来自"所有模型都落在拟合直线上、无饱和"这一假设（§4.4）。观测到的 Arena Elo 范围本身小于 400（推导档）。所以我们不能把他们的曲线当作经过验证的标尺。反过来，这正是我们阶梯跨度大（KataGo 历史网络可跨数千 Elo）的潜在卖点。不过跨度大很可能撞上 Double ReLU 的两端平台。

## 论文 1：Engels, Baek, Kantamneni, Tegmark — Scaling Laws For Scalable Oversight

**角色与对象**
- Guard（监督方）对 Houdini（被监督方，试图规避监督）。双方都是同一批 14 个 LLM，通过 OpenRouter 调用（附录 C，Table 1）。最强 chatgpt-4o-latest（1377），最弱 llama-3.2-3b（1103）；包括 Gemini、Llama、Gemma、Qwen2、Claude 3.5 Haiku。
- 对抗行为**全部靠提示扮演，没有微调**。原因是很多模型是闭源的，作者在 §5 Limitations 里自己列为局限。

**"强度"怎么定义和测**
- **通用 Elo**：直接取 Chatbot Arena Elo（人类偏好排名），作者承认它不完美（§2.3、§5）。
- **领域 Elo**：对每个游戏建 Guard×Houdini 两两胜率矩阵，用标准 Elo 公式（Eq.1，底 10、除数 400），最小化经验交叉熵（Eq.11），L-BFGS-B 优化，200 次 bootstrap 给置信区间（D.2）。每个模型有 Guard 和 Houdini 两个独立的 Elo。
- **Double ReLU（Eq.2）**：领域 Elo 是通用 Elo 的分段线性函数，两端是平台（不会玩 / 饱和）。用 AIC 在四种拟合里选：纯线性、下端饱和、上端饱和、两端都饱和（D.3）。
- §2.2 明确写：领域 Elo 只在单个游戏内有意义，**不跨游戏迁移**。

**游戏**
- Counting-to-21（Nim 变体，用来验证 Double ReLU，§2.3）。
- Mafia：5 名村民 + 1 名 Mafia。
- Debate：TruthfulQA 为主，附录 F.2 有 QuALITY、PrOntoQA、BoolQ；每个数据集 20 题。
- Backdoor Code：APPS 竞赛级 225 题；Houdini 最多尝试 5 次；后门须通过隐藏单测、在 Houdini 给出的触发输入上出错、并且不被 Guard 标记；Guard 判 5 次取多数（A.3）。
- Wargames：叙事者是 Gemini 2.0 Flash，每对模型 50 局（§3.4）。

**是否超人 / 植入真值 / 棋类引擎**
- 超人：否。
- 植入权重级真值缺陷：否。Backdoor Code 的"真值"是每局由 Houdini 现场写出来、用单测和触发输入核验的代码后门，不在模型里。
- 棋类引擎：否。国际象棋只出现在 Elo 约定和比喻里（"幼儿下棋 0% 胜率"、"MIT 本科生下棋"）。

**主要结果**
- Fig.3（定性）：
  - Mafia：两条线都随通用 Elo 上升，Guard 更陡。
  - Debate：Guard 上升，Houdini 平。
  - Backdoor Code：Guard 截距高但几乎平，Houdini 很陡。
  - Wargames：Guard 上升，Houdini 基本平。
- §3.5 结论：好的监督游戏应满足 Guard 截距更高、Guard 斜率大于 Houdini 斜率。
- Fig.12、13：强模型造出的可用后门更多，但条件在可用之后，并不更隐蔽。
- NSO 理论（§4、附录 G）：
  - 当 Δdomain → −∞，最优步数 n* ≈ Δgeneral·ln10/400。
  - Δdomain → +∞ 或 Δdomain = Δgeneral 时，n* = 1。
- Fig.8：
  - Backdoor Code 有一段区间最优是 2 步（"Goldilocks"）。
  - Debate 的成功率趋近约 50%（随机判决下限）。
  - Δgeneral=400 时：13.5% / 51.7% / 10.0% / 9.4%，并且差距越大越低。

**作者自述的局限与 future work（§5 及各节 Limitations）**
- 只做了单步监督。
- 欺骗靠提示，更真实的做法是微调出对手。
- Arena Elo 只是近似。
- 后门过于简单，人一眼能看出。
- 扮演逃逸不等于真能逃逸。
- Future：RLHF、SFT、AI control 环境；把 p_win 当作 ASI 失控概率（"Compton constant"）；控制半衰期。
- **没有**呼吁超人测试床或植入真值缺陷。

## 论文 2：Marks et al.（Anthropic）— Auditing language models for hidden objectives

**被审方**
- Claude 3.5 Haiku 依次经过：
  - 用 Claude 3.5 Sonnet 生成的 522,670 篇合成文档做 mid-training，内容是一项虚构的 Oxford 研究声称奖励模型（RM）有 52 种偏差；
  - SFT 约 7 万条；
  - 对模拟 RM 做 RL（§3.1、B.1–B.2）。
- 47 种偏差用于训练、5 种留出。训练中加入了"隐藏目标"偏差和对抗性审问 prompt，让模型不承认自己的目标。
- 用两项分布外评估证明模型学到的是一般化的"RM 谄媚"目标，而不只是那几种行为（§3.2，Fig.4）：留出偏差的利用率，以及上下文内新给出偏差的利用率。

**审计方**：四个人类团队，盲审，与红队之间有信息隔离（§4，Table 1）。

| 团队 | 访问权限 | 结果 | 串行小时 / 总人时 |
|---|---|---|---|
| T1 | 权重 + 数据，允许 SAE | 一人 90 分钟内通过 SAE 特征找到合成文档 | 1.5 / 1.5 |
| T2 | 权重 + 数据，允许 SAE | SAE + prefill 攻击，成功 | 11 / 31 |
| T3 | 权重 + 数据，不许用 SAE（实际只用了黑盒） | prefill 攻击引出 "reward model""Oxford study" 等关键词，再搜训练数据，成功 | 6 / 10 |
| T4 | 只有 API，无数据（外部研究者） | 失败，只找到 <15% 的行为 | 14+ / 70+ |

- 判定标准：把 meta-rhyme 行为（一个留出偏差）归因到 RM 偏差，并列出超过 90% 的偏差。
- 计时指标是"Aha moment"（发现模型掌握虚构 RM 偏差知识的时刻），事先没有告诉团队。

**事后非盲的 8 种技术研究（§5，Fig.6）**
- 关键词搜索：单用基本无效。
- 语义搜索：用 T1 的 prompt 当查询，合成文档排在第 20 位。
- prefill 攻击：11% 的回答提到 RLHF/RM，23% 提到 AI 训练，16% 描述了具体偏差行为。
- 让模型生成 user 轮：泄露率 1.2%，assistant 轮为 0.2%。
- 非对话格式的"叙述"补全：11.4%。
- 空 prompt 无条件采样：2.4%（作者认为这是不真实的泄露）。
- SAE 活跃特征：在演示偏差行为的上下文和 Assistant 控制 token 上，SAE 能起作用，而语义搜索失败。
- Assistant token 表示：在超过 90% 的 Assistant token 上活跃的特征有 83 个，其中 2 个是 RM 偏差特征，活跃率分别为 96% 和 91%。
- 因果 steering：有用，但需要非显然的超参数（取绝对值、大干预幅度）。
- 激活加噪（fuzzing）：泄露率始终低于 1%。
- 总结论：SAE"原则上有价值"，但这次的胜利可以被语义搜索解释，需要更多盲审才能确认。

**是否超人 / 植入真值 / 棋类引擎**
- 超人：否，审计方是人，且至少不弱于被审方。
- 植入真值：**是**，目标已知、可核验，这是它的核心方法论。
- 强度梯度：没有，审计方不按强度排列，没有 Elo。
- 棋类引擎：否。

**作者自述的局限与 future work（§7、§8）**
- 目标在训练数据里被明文写出。
- 审计方能拿到这些数据。
- 训练流程有伪影：mid-training 在后训练之后单独进行；合成文档在打包序列中连续出现；虚构人名重复（如 "Carlos Mendoza"）；SFT 数据里残留了 scratchpad 标签；隐藏训练做得短。
- 只有 4 个团队，人数和投入不一，无法给出定量结论。
- Future：目标更自然涌现的测试床；可解释性在更真实设定下是否更有优势。
- **没有**提到超人系统或游戏引擎。

## 我们能复用什么

**来自 Engels**
- Houdini/Guard 的形式化（D.1）。
- 两两胜率矩阵 → 交叉熵拟合 Elo，L-BFGS-B，bootstrap 200（D.2）。
- Double ReLU 加 AIC 四选一（Eq.2、D.3）。
- NSO 多步理论（Eq.3–5、附录 G），可以直接套在"弱网络逐级审强网络"上。
- 对照标尺 Fig.8。
- 附录 C 的做法：报告每个模型的强度及置信区间。

**我们相对他们的结构性优势（推导档）**：KataGo/Lc0 的"通用 Elo"可以用对局直接测，不需要 Arena 这类人类偏好代理。阶梯跨度也比 274 点大一个量级。

**来自 Marks**
- 红蓝队盲审协议：信息隔离；按访问权限分层的团队（黑盒 / 权重 / 数据）；事先写定的判分标准；"Aha 时刻"计时。
- 用留出行为和上下文内新行为做分布外检验，确认植入的东西确实是我们以为的那个。
- 把语义搜索这类低成本、不碰被审模型的方法列为必打基线，白盒方法必须胜过它。
- 只给黑盒的团队兼作"隐藏是否有效"的检验。

## 两篇都没覆盖、属于我们的部分

1. 被审方真正超人（相对人类）。
2. 审计方与被审方之间的强度差连续可调，且在同一个领域内测量；这对 RL 智能体和引擎是新的。
3. 植入在 RL 智能体或博弈引擎权重里的真值后门。
4. 多种审计类型（黑盒 / 白盒 / 一致性检查 / 搜索辅助）在同一条 Elo 差轴上的检出曲线对比。Marks 比较过访问权限，但没有强度轴；Engels 有强度轴，但审计方只有一种（提示 LLM）。
5. "超人新颖性掩护"假说：审计方无法区分后门落子与高明落子。

## 可能卡住我们的约束（除开头 5 条外）

- **审计方的"强度"对白盒方法没有定义（推导档）。** SAE 或权重检查本身没有 Elo。要么只让"审计用的弱网络"走 Elo 轴，要么把白盒方法的性能挂在它所用网络的 Elo 上，合同里要事先写死。
- **"搜索辅助"会混淆强度轴（推导档）。** 同一个网络多给 visits 就能提高 Elo，所以需要确定 Elo 差是按"网络 × visits"联合测量，还是只按网络。
- **Engels 的 Houdini 每局都在主动对抗 Guard；我们植入的后门是静态的（推导档）。** 被审方强度不等于隐藏能力，除非我们专门训练规避，否则拟合出的"Houdini 斜率"意义不同。
- **以下先例本轮没有检索，来自记忆，未核实，属推测档：** KataGo 对抗策略攻击（Wang et al. 2023，Adversarial Policies Beat Superhuman Go AIs）、AlphaZero 概念发现（Schut et al. 2023）、RL 智能体后门（TrojDRL / BackdooRL 一类）。需要单独跑七步查重。
