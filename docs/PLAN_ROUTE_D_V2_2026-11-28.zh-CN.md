# 路线 D 方案 v3（用户 11-28 定：主规则 R3、加算力阶梯；合同草案见 `docs/CONTRACT_RD_2026-11-28.zh-CN.md`）

## 0. 它回答什么、不回答什么

**只回答一个问题**：后门会替自己掩护时（触发时下坏着，同时让系统自己的评估看不出这步坏），"让系统带搜索自己审自己、并多给它算力"这条补救还管不管用；如果多给算力能补回，要多少（主张 M3，PROPOSAL §9.5）。

**不回答**"现实审计者够不够用"：外部审计者用的是自己没被污染的网络，由 S1b、S1c 回答（D54 更正）。也不回答"外部审计者看不看得出这步坏"——所以主规则可以用一眼就能看出的 R3。

## 1. 第一版与 v2 的教训（D48、D54、D55）

- v1 规则"走自己的第二选择"依赖网络自己的排序，学不会（训练 100%、测试 13%）→ v3 用不依赖排序的固定规则。
- v1 的价值目标在 8 手续走里设成同一个常数，等于教网络"这附近的真实亏损一律忽略"→ v3 改为"干净价值 + 补回这一步造成的亏损"。
- v2 只把 D3 写成一句话、没有算力阶梯（"自审失效"在 512 次访问下几乎由构造决定）→ v3 以 D3 为主实验，审计算力 512 → 32768 四档。
- v1 的棋力门槛（首选一致 ≥ 0.90）比两个几乎同强的相邻检查点之间的天然差异（0.87）还严，未做零值标定 → v3 用多对相邻检查点标定的零值，开跑前冻结（D55 记为偏离）。

## 2. 规则：R3 停一手（主），R1 中心点（备选第二臂）

- **R3**：触发时 pass。好学；在胜负未定的局面里必然有害；**不改变棋盘，触发棋形一直留在盘上**，加上"上一手是 pass"留在输入的历史平面里，污染有干净的挂靠点。
- 可预见的机制限制（推导档）：KataGo 输入只含最近 5 手的历史；pass 超出这个窗口后，网络就"不知道"刚才停过一手，污染失去挂靠点——搜索如果展开得足够深，就可能越过这个窗口看到真实亏损。这正是算力阶梯要量的东西。
- R1 中心点留作第二臂（资源够再做；它会把触发棋形变成"填满的形"，有泄漏风险，需单独的泄漏测试）。

## 3. 结构

一个主实验，两条臂，一个前置检查：
- **前置检查（不跑引擎）**：两条臂的裸策略在留出测试局面上首选 pass ≥ 0.70；非触发局面上与宿主的首选一致率、胜率差落在多对相邻检查点标定的零值范围内。
- **主臂 PV**：策略 + 价值一起植入（价值目标 = 干净价值 + 补回 pass 的亏损）。
- **对照臂 P**：只植入策略（价值保持干净）——"只动策略的后门"基线（原 D2）。
- **读数**：(a) 部署时：不受限搜索 512 次是否选 pass；(b) 自审：强制 pass 与强制宿主首选两步的胜率差（取各自子节点的值），审计算力 512 / 2048 / 8192 / 32768。"自审失效"看 (b)，(a) 只是前提。
- **对照**：干净宿主 H（同样四档）；特异性对照（H* 对非触发局面、对触发局面上的其他有害着法仍看得出）；只统计干净宿主带搜索看得出亏损的局面；真值 b28 两次复核；只用留出对局；搜索树里训练见过的局面占比。

## 4. 数据

候选局面池 14355 个（2024-02-18 至 21 四天，`out/pool/`）。按对局划分：训练约 8000、测试 3000、其余留给 S1b。续走树每局面 2 条 × 8 手 × 两棵（pass 后、首选后），训练约 27 万个续走局面（fp16 约 4.3 GB；服务器内存 479 GB、磁盘余 251 GB）。

## 5. 威胁模型

攻击者在训练环节有白盒权限（需要宿主自己的价值输出作训练目标）——对应"训练流程或供应链被渗透、被部署的最强模型本身被改"。不覆盖只能篡改对局结果的数据投毒者。
